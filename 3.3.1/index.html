3.3.1

The release after 3.3.0. The tasks of the world share one thread, the autosave copies the player before it writes, and a packet that writes no byte is no longer sent.

25 November 2026

The full list is the changelog. The changes a running server meets are these. The release also ships with known defects; the note One thread owns the blow names them.

One thread for the world

Movement, the knownlist, effects, AI and the logic of client packets run as tasks on one platform thread, l2jfree-world, so two of them cannot write one creature at the same time. The global tasks, the item flush, dropped items, the game clock and the character load wait for the database on virtual threads. A rift tick, an Olympiad step, a Festival step and a GM command apply as one step on the world thread. BaseThreadPoolSize and ExtraThreadPerCore are no longer read; a file that still names them is not an error.

What still waits

A logout's own save, the commit of a multisell exchange, an admin command and the creation of a character still wait for the database on the world thread, and a slow database holds the other world tasks for that time. A task that runs longer than five seconds is logged, and an admin command that runs that long tells the GM. No load measurement has been made.

Saves

The autosave copies the character row, the subclasses, the cooldowns and the effects on the world thread and writes that copy in the background. A summoned pet is still read by the write, and so is the inventory when UpdateItemsOnCharStore is on; it is off by default. A character that already left the world is not saved again on disconnect.

Network

A packet that writes no byte is not sent as an empty frame. The client no longer reads a frame with nothing in it after a logout.
